How the CSV merge and CRM check works

The skill takes two or more contact or company lists in CSV format, merges them into one list without duplicates, adds facts from Apollo, checks HubSpot to see who we already know, and recommends what to do with every row. It only reads from Apollo and HubSpot and never changes them. Each numbered step below does one job, and the finished file is at the bottom.

Works on the files only Matching inside the files Asks Apollo Asks HubSpot

Start: two or more CSV files go in

You upload your lists and ask to merge, clean up or check them against HubSpot. Nothing in the original files is changed. Every result is written into new columns.

The CSV files

Lists of companies and/or people, for example exports from different tools or events. Different column names are fine.

The connections it uses

Apollo (contact database) and HubSpot (our CRM). Both are read-only unless you explicitly ask the skill to write.

1

Open and inspect the files

Works on the files only

Reads every uploaded CSV file and reports what is in it, so problems show up before any work starts.

Result: a short overview of each file, or a clear request for a corrected file.

1a. What is checked

The file format, how many rows and which columns each file has.

1b. Spotting identifiers

Which columns probably identify a company (website, LinkedIn page, name) or a person (email, LinkedIn page, full name).

File cannot be read

The skill explains the problem and asks you for a corrected file.

2

Give columns the same names

Works on the files only

Different files call the same thing different names ("company", "organization", "account"). The skill maps them to one standard name.

Result: both files use the same column names.

2a. Examples

"company", "organization" and "account" all become company_name. "work_email" becomes contact_email. "title" and "position" become contact_title.

2b. LinkedIn links

The skill decides from the link whether it belongs to a company or a person.

2c. Nothing is lost

If renaming would destroy information, the original column is kept with the prefix original_.

3

Clean the values

Works on the files only

Removes small differences that would stop two records from being recognised as the same.

Result: tidy, comparable values.

3a. Basic tidying

Extra spaces are removed, emails and web addresses are written in lower case, and tracking parts of links are removed.

3b. Standardise web addresses

https://www.fielmann.eu/ becomes fielmann.eu.

3c. Company endings

GmbH, AG, Ltd, Inc, KG and similar endings are ignored for comparing only. The original name stays as it was.

4

Combine the files and remove duplicates

Matching inside the files

Puts all files into one list and finds records that are the same company or the same person. It is deliberately careful: when in doubt, it does not merge.

Result: one list without duplicates, with the columns source_file, source_row_id, dedupe_key and merge_status.

4a. Same company? strongest proof first

1. Same company website. 2. Same cleaned web address. 3. Same LinkedIn company page. 4. Same company name and country. 5. Very similar name, only if confidence is high.

4b. Same person? strongest proof first

1. Same email. 2. Same LinkedIn profile. 3. Same full name and company website. 4. Same first name, last name and company name.

4c. Not sure

Nothing is merged. The row is flagged ambiguous_duplicate for a person to review.

4d. Every row is traceable

Each row remembers which file and which line it came from.

5

Add company and contact facts

Asks Apollo

Asks Apollo, our contact database, for facts about each company and person on the list.

Result: columns starting with apollo_ and a confidence rating for each row.

5a. Companies are looked up by

Website, then LinkedIn company page, then company name plus country.

5b. People are looked up by

Email, then LinkedIn profile, then full name plus company website, then full name plus company name.

5c. What is added

Company and contact IDs, official name, website, industry, number of employees, revenue, country, LinkedIn page, email and job title.

5d. Confidence rating

high: exact website, email or LinkedIn match. medium: strong name plus website match. low: name only or partial. none: nothing found.

Several possible matches

The row is marked ambiguous with the action "manual Apollo review". Nothing is invented. Fields stay empty when Apollo has no data.

Apollo rate limits

If Apollo slows down, the available rows are done and the report says that enrichment is incomplete.

6

Check HubSpot

Asks HubSpot

Looks in HubSpot, our CRM, to see whether each company and person already exists, and whether we are already working with them. This is read-only. Nothing is written to HubSpot unless you explicitly ask.

Result: columns starting with hubspot_ and an enrollment status for each row.

6a. Companies are searched by

Website, then LinkedIn page, then exact name plus country, then a similar name (only if one clear match exists).

6b. People are searched by

Email, then LinkedIn profile, then first and last name plus company website, then full name plus company name.

6c. What is collected

Company and contact IDs, linked deals, lifecycle stage, owner, last activity date, and notes or flags.

6d. Enrollment status in plain words

confirmed_enrolled: clear proof the person is in a sequence, workflow or list. likely_enrolled: strong hints such as an active deal or recent activity. existing_not_enrolled: record exists, no sign of enrollment. not_found: not in HubSpot. ambiguous: several possible matches. unable_to_determine: record found but enrollment data missing.

6e. Always explained

The skill states which fields it used to reach the status.

7

Recommend what to do with each row

Works on the files only

Turns everything learned so far into one clear suggestion per row, so nobody has to interpret the raw data.

Result: the column recommended_action.

Skip: already in HubSpot

skip_existing_in_hubspot. A strong HubSpot match that is already enrolled or actively owned.

Review the HubSpot record

review_existing_hubspot_record. A match exists but it is unclear whether the person is enrolled.

Safe to import

safe_to_import_or_enroll. No HubSpot match and the data is good enough.

Needs a person

manual_review_required. Unclear match, incomplete data or low confidence.

Fill the gaps first

enrich_missing_identifiers_first. The website, email or LinkedIn link is missing.

8

Mark data quality problems

Works on the files only

Adds warning labels to rows that have missing or doubtful information. Several labels can sit in one cell, separated by semicolons.

Result: the column data_quality_flags.

8a. Missing information

missing_domain, missing_email, missing_company_name, missing_contact_name.

8b. Apollo problems

apollo_no_match, apollo_ambiguous_match.

8c. HubSpot problems

hubspot_no_match, hubspot_ambiguous_match, hubspot_existing_record, hubspot_enrollment_unknown.

8d. Other

ambiguous_duplicate, low_confidence_match.

9

Build the final file and summary

Works on the files only

Writes the merged, enriched and checked list to one CSV file and sends a short summary of what happened.

Result: one CSV file and a summary in the chat.

9a. If a system is unavailable

Apollo down: you still get a merged file ready for Apollo. HubSpot down: you get an enriched file ready for a HubSpot check. Both down: you get the merged, duplicate-free file with an explanation.

9b. Privacy

All uploaded data is treated as confidential. The summary shows no unnecessary personal data, and the skill never infers private emails or personal details.

End

Output: the merged and checked CSV file

You get one clean CSV file with every row marked with a recommended action, plus a short summary in the chat. Where a result is uncertain, the row is labelled so you know where to look first.
