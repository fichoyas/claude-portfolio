HubSpot Contact Enrichment & Non-Accepted Email Analyzer

Overview: Enriches an uploaded Apollo contact workbook with factual HubSpot CRM identifiers, color-coded last-contacted dates, and deal associations—then invokes a deterministic Python script (analyze_nonaccepted_emails.py) using up to 10 verified HubSpot colleague emails per company to infer missing/non-Accepted email formats with strict confidence scoring.

Supplements: 📊 Apollo Contacts File + HubSpot Companies Lookup File 🐍 scripts/analyze_nonaccepted_emails.py 🟠 HubSpot CRM Connector (Zero-Fabrication Rule)
Step 1 • Content-Based Input Inspection

Distinguish Apollo vs. HubSpot Files

Identifies files by column structure (Contact columns vs. Company Domain + Record ID). Reads all Record IDs strictly as text (dtype=str) so long IDs never corrupt into floats or scientific notation.

Guardrail: Preserves all source data; halts if lookup file is missing
Step 2 • Sandbox Domain Normalization & Company ID Lookup
Exact Domain Match

Copy Company Record ID

Matches normalized bare domain in Python sandbox (saving API tokens) and computes Number of Contacts per domain. No cell fill.

v1 Mode Option: Queries HubSpot API once per unique domain
Close Match (≥90% / TLD)

Copy ID + Flag Yellow

Matches alternate TLD (.com vs .de) or SequenceMatcher ≥ 0.90. Populates ID and colors cell Yellow.

Ambiguous Ties: Treated as unmatched (left blank)
No Match / Conflict

Leave Blank & Report

Leaves Company Record ID blank with no fill. Reports duplicate conflicting lookup IDs to user.

Rule: Never invent or guess a Company Record ID
Step 3 • Contact Resolution & Latin Fallback

Retrieve Verified Contact Record ID

Searches HubSpot by First + Last Name and confirms match against the resolved Company Record ID. Retries with Latin transliteration (Weiß → Weiss, Østergaard → Ostergaard) if needed.

Gate: Only contacts with a verified Contact Record ID advance to Step 4
Step 4 • Retrieve Last Contacted & Deal Associations
4.1 • Last Contacted

3-Month Cutoff Color Coding

Writes YYYY-MM-DD or never contacted. Colors cell Red if contacted < 3 months ago, or Green if ≥ 3 months ago.

API Failure: Leave blank (never write "never contacted" on error)
4.2 • DEAL Status

Check Deal Associations

Checks any deal stage (open, won, lost). Writes DEAL, NO DEAL (confirmed zero), or NO LOOKUP (on API error).

Guardrail: Never write NO DEAL if lookup failed
🐍 Step 5 • Deterministic Non-Accepted Email Analyzer (analyze_nonaccepted_emails.py) Skips rows where Email Verification == "Accepted"
Steps 5.2 & 5.3 • Factual Colleague Sample JSON

Fetch Up to 10 Colleagues per Company Record ID

For rows with non-Accepted statuses (catch-all, greylisted, mx-error, SPAM block), retrieves up to 10 factual colleague emails from HubSpot (excluding the target contact) and writes temporary JSON.

17 Canonical Patterns: first.last, flast, f.last, first_last, last.first, etc.
Self-Exclusion: Target contact never used as evidence for their own pattern
≥2 Colleagues & ≥70% Share
High Confidence

Writes dominant format to Claude Guess (or leaves blank if original email already matches).

1 Sample or <70% Share

Populates Claude Guess from dominant pattern; leaves guess blank if tied.

0 Usable Colleagues

Never fabricates a pattern without factual HubSpot colleague evidence.
