How the HubSpot contact enrichment skill works

The skill takes a list of sales contacts from Apollo and adds what our CRM, HubSpot, already knows about them. It also suggests a fix for email addresses that look wrong and writes a greeting for each contact. Each numbered step below does one job, and the finished Excel file is at the bottom.

Start: two files go in

You run the skill by name and upload both files. Nothing is changed in the original data. Every result is written into new columns.

Apollo file

The contact list to enrich: names, titles, company names, websites, email addresses and the email check result.

HubSpot file

A list of companies with their HubSpot Company Record IDs. It is used as a lookup table so the skill does not have to search HubSpot for every company.

1

Read and prepare both files

Works on the files only

Works out which file is which and tidies the data so the later steps can compare it reliably.

Result: both files are ready for matching.

Tell the two files apart

The file with people and emails is the Apollo file. The file with companies and IDs is the HubSpot file. If it is unclear, the skill asks you.

Keep long IDs intact

IDs are read as text so a long number never turns into scientific notation.

Standardise web addresses for comparison

https://www.fielmann.eu/ becomes fielmann.eu. This is used only for matching. The original cell is never changed.

2

Find each contact's company

Matching inside the files

Looks up each company in the HubSpot file and copies its Company Record ID. It tries four ways, in order, and stops at the first one that works.

Result: the columns Company Record ID and Number of Contacts.

Saves time: no HubSpot search is needed for companies.

2a. Website address tried first

The contact's website matches a company website in the HubSpot file exactly.

2b. Company name tried second

The company name matches. Endings such as GmbH, AG or KG are ignored. Example: "Fielmann AG".

2c. Email domain tried third

The part after the @ in the contacts' emails matches a company website in the HubSpot file. Example: @intersnackgroup.com.

2d. Look-alike domain tried last

A very similar website, for example ikea.com and ikea.de. The cell is coloured yellow so a person double-checks it.

No match

The cell stays empty. The skill never guesses an ID.

Number of Contacts

Counts how many people from the same company are in this file. Four people from Deutsche Bahn means the number 4 on each of those rows.

3

Find each person in HubSpot

Asks HubSpot

Checks whether each contact already exists in HubSpot and gets their Contact Record ID.

Result: the column Contact Record ID. Empty means the person is not in HubSpot yet.

Saves time: one search covers all emails at once.

3a. Search by email first, all rows at once

If the email is identical, it is the same person. This holds even when HubSpot spells the name differently, for example with a middle name, or files the person under another company record.

3b. Search by name inside the company for the remaining rows

Looks for first and last name within the matched company. It also tries other spellings: Müller and Mueller, hyphenated names, and prefixes like "v." or "von".

Not found

The cell stays empty. Nothing is invented.

4

Pull the sales history

Asks HubSpot

For every person found in step 3, reads when we last contacted them and whether they are linked to a deal.

Result: the columns Last Contacted and DEAL.

4a. Last Contacted

Shows the date, or never contacted. The colour shows how recent it is:

red contacted within the last 3 months, so be careful about reaching out again.

green contacted exactly 3 months ago or longer ago.

4b. DEAL

DEAL when the person is linked to at least one deal. NO DEAL is written only after a second check confirms there are none.

5

Check doubtful email addresses

Asks HubSpot and runs a script

Looks at emails that were not verified and suggests a likely correct address, based on how colleagues at the same company are addressed.

Result: the columns Claude Guess and Claude Confidence.

5a. Choose the rows to check

Emails already marked Accepted are skipped. Everything else is checked.

5b. Collect colleagues' emails

Takes up to 10 emails from other people at the same company in HubSpot.

5c. Find the company's email pattern

A Python script counts the patterns, for example first.last@company.com, and finds the most common one. It handles umlauts (ü becomes ue) and hyphenated names.

5d. Write the suggestion

If the contact's email does not follow the pattern, the suggested address goes into Claude Guess. Claude Confidence shows High when the pattern is clear and Low when it is mixed.

Special rule for "Rejected" emails

A rejected address is known to be wrong, so the skill looks for a different email format that colleagues at the same company really use. If none exists, it writes No Alternative Found. It never invents a format. Greyer statuses (Catch-All, MX Error, Timeout) cannot be proven wrong, so they are only changed when they clearly break the pattern.

6

Check suggested emails against the whole CRM

Asks HubSpot

Looks for each person from step 5 in the whole HubSpot CRM. It flags people who may already exist there and makes sure no suggested address belongs to someone else.

Result: the column Potential Duplicate, and suggestions that are safe to use.

6a. Search by name and company domain

HubSpot is searched across the whole CRM by last name and the company's email domains. "Same company" means the same name before the ending (amazon.com and amazon.de) or any email domain that colleagues at that company use, for example both pfeifer-langen.com and pfeifer-langen-ihkg.com.

6b. Same name, same company: potential duplicate

The existing contact's email address goes into the Potential Duplicate column for a person to review. The suggestion itself is not changed. If the person's Contact Record ID is empty, it is filled in with last contacted and deal status.

6c. Same name, different company: ignored

Two people can share a name. Nothing is flagged or reported.

6d. Address belongs to someone else: blocked

If the exact suggested address belongs to a contact with a different name, it is never suggested. A rejected email moves on to another format colleagues really use, or No Alternative Found. Other emails are left without a suggestion. The report names the owner.

7

Add the salutation

Works on the files only

Writes the right greeting for each contact, in the language of their country. It reads four things per contact: first name, last name, country and LinkedIn address.

Result: the column Salutation.

7a. Language from the country

The contact's country decides the language. Germany, Austria and Switzerland get Herr or Frau, France gets Monsieur or Madame, the UK and US get Mr or Ms. If the country is empty or not covered, the cell stays empty.

7b. Title from the LinkedIn address

Looks for the whole words "dr" or "prof" in the profile name, for example linkedin.com/in/dr-nina-wendel. It adds Dr. or Prof., or Prof. Dr. when both appear.

7c. Mr or Ms from the first name

Claude decides from the first name, using the country as context. If a name could be either, the cell stays empty so nobody gets the wrong greeting.

7d. Put it together

Examples: Herr, Frau, Herr Dr., Frau Dr., Herr Prof. Dr.. Salutations that already exist in the file are kept, and only empty cells are filled.

✓

Final checks before delivery

Works on the files only

Verifies the work and looks through every row for odd entries.

Result: a clean file and a short list of rows for a person to review.

Original data untouched

Every column that was in the Apollo file is identical to the upload.

IDs are real

Every Company Record ID appears in the HubSpot file. Verified emails were left alone, and the contact counts add up.

Row-by-row review

Odd rows are reported, never silently fixed. Examples: a first-name cell holding the full name, an email that does not fit the name, or an email from an unrelated company.

End

Output: the enriched Excel file

You get the same table you uploaded, plus nine new columns. Nothing that was already in the file is changed. Where a result is uncertain, the cell is coloured so you know where to look first.

Company Record ID
The company's HubSpot ID, copied exactly from the HubSpot file. Yellow means it was matched by a look-alike domain, so please check it.
Number of Contacts
How many people from the same company are in this file, centred in the cell.
Contact Record ID
The person's HubSpot ID. Empty means the person is not in HubSpot yet.
Last Contacted
The date of the last contact, or "never contacted". Red is within the last 3 months. Green is 3 months ago or longer.
DEAL
DEAL if the person is linked to a deal. NO DEAL if that was confirmed.
Claude Guess
A suggested email address for doubtful emails, always based on formats colleagues really use in HubSpot. No Alternative Found appears when a rejected email has no evidence-based replacement. Empty when the existing email looks fine or is already verified.
Potential Duplicate
The email address of a contact already in HubSpot who appears to be the same person as the suggestion. Left for a human to review.
Claude Confidence
High when the company's email pattern is clear. Low when the pattern is mixed or the suggestion replaces a rejected address.
Salutation
The greeting in the language of the contact's country, for example "Frau Dr." or "Herr". It is added after the last name if the file has no such column. Existing entries are kept.
